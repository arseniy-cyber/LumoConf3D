# Проверка панели управления

Панель проверена в Chromium через Playwright на локальной production-сборке Vite, Cloudflare Pages Functions и изолированной D1. Размеры области просмотра 1440 × 940 на компьютере и 360 × 800 при эмуляции сенсорного телефона. Временная база заполнена миграциями каталога и локальной заявкой для проверки смены статуса. Для входа использованы тестовые аккаунты. Скриншоты входа, обзора, каталога, редактора крепления и мобильного обзора проверены визуально.

| Сценарий | Ожидаемый и полученный результат |
|---|---|
| Анонимный посетитель | Панель открывает форму входа, API каталога администратора отвечает 401. |
| Вход владельца | Верные пароль и код TOTP открывают панель. Сессия использует HttpOnly и SameSite=Strict. Метрики прочитаны из D1. |
| Поиск и экспорт | Поиск находит Ryzen 7 7800X3D. Запрос без совпадений показывает пустое состояние. Экспорт скачивает каталог. |
| Редактирование и крепление | Загруженный PNG доступен по адресу Worker. Перемещение точки на схеме и ввод поворота сохраняют координаты и угол в D1. |
| Поля модели | Пять повторных проверок в разделах корпуса, процессора, видеокарты, охлаждения и накопителя подтвердили независимость наименования и пути модели. В разделе процессора загружен локальный GLB с корректным MIME-типом и сигнатурой. |
| Архив и восстановление | Комплектующее получает статус «В архиве» и восстанавливается через ту же карточку. |
| Импорт | Загруженная JSON-позиция появляется в поиске после подтверждения. |
| Готовые сборки | Сборка с выбранным комплектующим сохраняется и появляется в списке. |
| Настройки и промокод | Название магазина и код скидки сохраняются через API. |
| Заявки | Карточка показывает клиента. Изменение статуса доступно после повторного чтения из API. |
| Сотрудники и журнал | Для нового пользователя создаётся ключ TOTP. Событие создания появляется в журнале. Выход возвращает форму входа. |
| Роль поддержки на мобильном экране | Пользователь входит со своим TOTP. Раздел каталога скрыт, прямой запрос возвращает 403. Горизонтальное переполнение страницы отсутствует. |
| Исключения JavaScript | Во время пройденного настольного сценария исключений страницы не зарегистрировано. |

В первоначальной проверке Playwright нашёл одинаковые имена полей «Модель» и «Путь к модели» в форме. Поля получили разные имена. Повторные проверки прошли в пяти категориях и включали независимое редактирование наименования при загрузке GLB.

## Повторение

Поднимите локальную копию Pages и D1 по [инструкции сервера](BACKEND.md). Для копии используйте отдельный каталог состояния D1 и созданного локально владельца. В локальной проверке привязки Worker получили независимые тестовые значения `ADMIN_PASSWORD_KEY`, `ADMIN_TOTP_KEY`, `RATE_LIMIT_KEY` из `.dev.vars` в корне тестовой копии.

Тест читает пароль из файла `password`, а результат `scripts/bootstrap-admin.mjs` с URI для аутентификатора из файла `enrollment`. Храните оба файла в закрытом каталоге временных данных. Для проверки смены статуса заявки подготовьте в тестовой базе запись `qa-order-001` с именем покупателя «Тестовый покупатель». Без этой записи тест проверит пустое состояние заявок. Скрипт допускает адреса loopback и создаёт тестовые товары, скидки, конфигурации и аккаунты в выбранной локальной базе.

```sh
LUMO_ADMIN_FIXTURES=/path/to/private-fixtures \
LUMO_ADMIN_TEST_ORIGIN=http://127.0.0.1:8793 \
LUMO_ADMIN_TEST_EMAIL=admin-check@example.test \
python3 tests/browser/admin.py
```

Скрипту нужны Python, Playwright и Chromium. Путь к Chromium можно задать переменной `LUMO_TEST_CHROMIUM`.
