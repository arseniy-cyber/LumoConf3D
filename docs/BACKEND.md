# Сервер, база и эксплуатация LUMO

Приложение раздаётся через Cloudflare Pages. Один обработчик обслуживает маршруты Pages Functions и отдельный Cloudflare Worker. Первый вариант сохраняет общий origin для сайта, форм и панели. Отдельный Worker полезен для внешнего API и фоновой очистки, его выпуск независим.

## Локальный запуск

Требуются Node.js 22.13+ и npm. Команды выполняются в корне репозитория.

```sh
npm ci
npm run db:migrate
npm run build
npm run dev:pages
```

Полный локальный сайт открывается на `http://localhost:8788`, административная панель на `http://localhost:8788/admin`. Миграции включают 58 товаров и готовые сборки. Для разработки с обновлением модулей запустите `npm run dev:api` и `npm run dev` в разных терминалах. Конфигурация Vite передаёт запросы к `/api` на порт 8788. Используйте одно имя хоста последовательно, чтобы браузер отправлял cookie и корректный Origin панели.

Чтобы включить локальную авторизацию, создайте три независимых ключа. Команда создаёт новый игнорируемый Git файл `.dev.vars` с правами 0600 и завершится ошибкой, если файл существует.

```sh
node --input-type=module -e 'import { randomBytes } from "node:crypto"; import { writeFileSync } from "node:fs"; writeFileSync(".dev.vars", ["ADMIN_TOTP_KEY", "ADMIN_PASSWORD_KEY", "RATE_LIMIT_KEY"].map(key => key + "=" + randomBytes(32).toString("base64url")).join("\n") + "\n", { flag: "wx", mode: 0o600 })'
```

Первоначальный владелец создаётся через CLI. Введите уникальную парольную фразу из 18–256 символов или пароль менеджера паролей. Команды ниже предназначены для Bash.

```sh
read -rs -p 'Пароль владельца: ' lumo_owner_password
printf '\n'
printf '%s' "$lumo_owner_password" | node --experimental-strip-types --env-file=.dev.vars scripts/bootstrap-admin.mjs --local --email owner@example.com
unset lumo_owner_password
```

Добавьте выданный TOTP URI в приложение аутентификации. Сохраните URI в защищённом хранилище и удалите его из доступных журналов терминала. После изменения `.dev.vars` перезапустите локальный сервер. Если запуск использует `--persist-to` или другой файл конфигурации, передайте те же параметры миграциям, CLI и dev-серверу.

## Подготовка Cloudflare Pages

1. Создайте отдельную D1 в аккаунте магазина. Выберите юрисдикцию, если она требуется для рынка. Запишите ID базы в поле `d1_databases[0].database_id` в `wrangler.jsonc` и при использовании отдельного Worker в `wrangler.worker.jsonc`.
2. Примените миграции в подтверждённую базу командой `npx wrangler d1 migrations apply lumo-builder --remote --config wrangler.jsonc`. Используйте отдельную конфигурацию и базу для предварительных окружений.
3. В Cloudflare Pages свяжите принадлежащий вам репозиторий GitHub. Установите корень репозитория, сборку `npm run build` и каталог вывода `dist`. Укажите утверждённую ветку после проверки. Маршруты Functions находятся в `functions/`, ограничения вызова в `public/_routes.json`.
4. Создайте три независимых 256-битных base64url ключа и сохраните их в секретах Pages `ADMIN_TOTP_KEY`, `ADMIN_PASSWORD_KEY` и `RATE_LIMIT_KEY`. Передайте те же административные ключи CLI через защищённый канал окружения для создания первого владельца. Используйте аргумент `--remote` вместо `--local` только после проверки аккаунта, D1 и конфигурации. Ротация ключа TOTP и серверной добавки к паролям потребует управляемого переоформления данных доступа.
5. Подключите утверждённый домен. Проверьте TLS и редирект HTTPS, затем проверьте HSTS на живом hostname. Корпоративные CORS-источники и домены iframe задаются отдельно в настройках магазина.
6. Сверьте параметры Pages. Free допускает до 25 МиБ на статический файл и до 20 000 файлов на сайт. D1 Free допускает до 500 МБ в одной базе и 2 000 000 байт на значение или строку. Workers Free даёт до 10 мс CPU на HTTP-запрос. Локальный запуск не проверяет этот лимит в облаке. Измерьте целевой тариф на HTTPS после подключения, в первую очередь вход с PBKDF2 и импорт крупного каталога.

Руководства Cloudflare [Pages Functions](https://developers.cloudflare.com/pages/functions/wrangler-configuration/), [лимиты Pages](https://developers.cloudflare.com/pages/platform/limits/), [лимиты D1](https://developers.cloudflare.com/d1/platform/limits/), [лимиты Workers](https://developers.cloudflare.com/workers/platform/limits/).

## Подключение Turnstile и Telegram

Для Turnstile создайте виджет с утверждённым доменом магазина. Сохраните публичный ключ в `TURNSTILE_SITE_KEY`, список допустимых имён хостов через запятую в `TURNSTILE_HOSTNAMES`, ключ Siteverify в секрете `TURNSTILE_SECRET`. Обновите публичные vars в конфигурации Pages. Форма передаёт действие `quote_order`. Сервер сверяет флаг успеха, действие и hostname, затем записывает хеш токена в D1 для защиты от повторного применения при конкурентных запросах. При отсутствии рабочих настроек оформление заказов отключается. После подключения отправьте тестовую заявку, затем проверьте, что повтор использованного токена отклоняется. [Turnstile Siteverify](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)

Для Telegram создайте бота и разрешите ему отправлять сообщения в выбранный чат. Сохраните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` и `TELEGRAM_STORE` как настройки на сервере. В `TELEGRAM_STORE` укажите slug соответствующего магазина. В панели откройте настройки и включите уведомления Telegram. Уведомление приходит после сохранения заявки, содержит её номер и сумму. Контактные данные остаются в панели. Сбой уведомления логируется, повторная доставка пока ручная. [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage)

## Новый магазин

Оператор заводит запись в `stores` и использует один безопасный slug в полях `id` и `slug`. Изолированные настройки, каталог, файлы, пользователи и заявки связаны с идентификатором магазина. Для продающего домена оператор регистрирует его в Pages и добавляет имя без схемы и порта в `store_hosts`. Без карты хоста запрашивайте витрину и панель с параметром `?store=slug`. Для iframe добавьте точные HTTPS origins сайтов магазина в `embedOrigins` и используйте путь `/embed?store=slug`. Для прямых cross-origin вызовов публичного API добавьте точные HTTPS origins в `apiOrigins`.

Оператор создаёт владельца через `scripts/bootstrap-admin.mjs --store slug`. Владелец может настроить витрину, создать сотрудников и импортировать данные из JSON. Поля `license_status` и `license_until` управляют приёмом заявок и разрешением встраивания. Действуют статусы `trial`, `active` и `suspended`. Сроки хранятся в UTC Unix timestamp. Для перевода на новый срок оператор изменяет запись D1 после договорного подтверждения. Автоматическое списание, выставление счетов и порталы подписок требуют отдельной интеграции.

## Управление товарами и файлами

Продукт в API имеет структуру `Part` из `src/shared/types.ts`. Цена задаётся целыми единицами валюты, исходная витрина использует RUB. Выберите статус цены `demo` или `verified`, добавьте HTTPS-источник и дату проверки. Для карточки укажите точные характеристики и происхождение изображения и 3D. Загружайте JPEG, PNG и WebP до 500 000 байт или самодостаточный GLB 2.0 до 1 500 000 байт. Сервер проверяет размеры изображения, части GLB, ссылки на ресурсы, допустимые расширения и предельный объём распаковки Meshopt. Позиционирование хранится в миллиметрах в `specs.mountOffsetMm` как объект `{x,y,z}` и в градусах поворота вокруг Y в `specs.mountRotationDeg`.

Исходные 3D и изображения поставляются статически. Загрузки из панели хранятся в D1. Условия хранилища и стоимость отличаются от статических ресурсов. Доступ к загрузке административный. Выданные адреса изображений и моделей общедоступны для просмотра товаров. Загружайте только коммерчески разрешённые материалы. При росте объёма замените сохранение и чтение в `worker/media.ts` на S3-совместимое хранилище с сохранением модели сопоставления tenant и идентификатора.

Архивирование скрывает товар из продажи, сохраняя снимки заказов. Импорт принимает до ста позиций за запрос, обновляя только присланные записи. Для изменений из панели новая миграция не нужна. После установки каталога на рабочей базе изменение исходного каталога требует дополнительной миграции или импорта. Утилита `node --experimental-strip-types scripts/generate-seed.mjs` повторно создаёт стартовую миграцию исключительно для создания новой базы до первого выпуска.

## Резервирование и проверки

Проверьте встроенную D1 Time Travel и выполните экспорт в отдельное защищённое хранилище по утверждённому расписанию. Сроки хранения D1 Time Travel на Free составляют семь дней. Экспорт может включать данные клиентов и административные хеши. Проверьте восстановление на отдельной D1 и храните резервный доступ к серверным ключам независимо от базы. [D1 Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/)

Команда `npm run test:api` выполняет проверки на локальном workerd и новой D1. Внешние ответы Turnstile и Telegram подменены на границе сети. Отдельно требуется подтвердить доставку уведомления, действующий виджет, резервное восстановление и расход CPU в облачной среде. Авторизация, токены проверки, временные ссылки и счётчики состоят из служебных данных со сроком истечения. Рабочий процесс очистки вызывается отдельным Worker по расписанию или выборочно при изменяющих API-запросах. Срок хранения данных клиентов определяется владельцем магазина с учётом выбранного рынка.
